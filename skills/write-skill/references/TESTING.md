# Fresh-Agent Behavioural Evaluation

Use this reference when scenario selection, context isolation, result variability, or observable pass evidence needs more detail than the common successful path.

## Preserve the evaluation boundary

Give the fresh agent the finished bundle, a realistic user request, and only task-local evidence. Keep the intended answer, design rationale, suspected failure, prior output, and hidden hints outside the evaluation context. Use an inert workspace or read-only artefacts; permit safe local writes only when the scenario requires them. An evaluation demonstrates transferable steering when the bundle and supplied evidence account for the process and result.

## Select scenarios

Run the common successful path for every created or rewritten skill. Add the smallest scenario for a retained material exception when it distinguishes:

- an evidenced invocation that changes the required process or result;
- a necessary safety, permission, or prerequisite boundary;
- an optional reference needed by the retained exception;
- a fragile script or deterministic output contract; or
- wording whose effect depends on a selected concept or precise instruction.

Prefer one scenario that distinguishes several competing behaviours when failure remains diagnosable. The scenario set contains only confirmed behaviour or material risk rather than quotas or hypothetical combinations.

## Define evidence

Translate the confirmed contract into observable pass conditions before reading the result. Inspect the agent's actions, resource reads, decisions, boundaries, result, and postconditions.

For variable work, judge whether the agent followed the confirmed process, used the correct authorities and resources, respected user decisions and stopping boundaries, and produced a correct result suitable for the supplied evidence. Do not require one hidden solution, route, or phrasing.

For fixed assets, schemas, scripts, formats, or deterministic behaviour, inspect the exact properties promised by the contract. Pass only when the degree of scrutiny matches the claim the skill makes.

## Repair the smallest cause

Trace each failure to the smallest instruction, pointer, section boundary, or missing resource that explains it. Repair that cause, then rerun the failed scenario and a common-path scenario. Recompress and mechanically revalidate after every material change.

Stop when every confirmed scenario passes or reducing the remaining variance would change the confirmed contract. Report unresolved variance plainly.
