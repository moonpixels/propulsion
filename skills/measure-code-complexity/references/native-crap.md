# Collect native CRAP

Inspect installed packages, test configuration, repository commands and supported reporting options. Verify uncertain flags against installed help or source. A test framework or coverage reporter alone does not establish CRAP support. Required instrumentation must already work.

Reuse a report only when its source, tests, configuration, command, tool version and scope are established as current. Otherwise run the project's existing test command with its supported CRAP report option. Preserve suite selection, exclusions, fixtures, runtime and thresholds. Write to a fresh temporary destination outside the repository. Reuse an ordinary verification run where possible.

Inspect the actual report. A successful command or requested filename without usable scores establishes no measurement. Check that source, tests and configuration stayed unchanged during collection. Record command, exit result, producing versions, source and test scope, and report path. The static CLI's content identity covers only selected source.

Retain native method identities and scores exactly as produced. Native tools own their complexity, coverage definition and formula. Keep them separate from static measurements. An unmatched method supplies no score. Install no packages, add no configuration or tests, and calculate no substitute CRAP from separate coverage. Without a usable facility, omit CRAP without setup advice or a testing-gap report. Report an attempted failure or stale report as an evidence limitation.
